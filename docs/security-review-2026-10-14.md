# بررسی و تقویت امنیت — ۱۴ اکتبر ۲۰۲۶

این بررسی روی کد همین مخزن، وابستگی‌ها و تنظیمات استقرار موجود انجام شد. اصلاحات در workspace هستند و روی سرور اصلی منتشر نشده‌اند. امنیت مطلق یا مقاومت در برابر DDoS زیرساخت با بررسی کد تضمین نمی‌شود.

احراز هویت مسیرهای مدیر، مالکیت منابع شخصی، نمایانی پروفایل‌ها، پاک‌سازی HTML، JSON-LD، مسیرهای فایل و مقصدهای مجاز واردکننده نیز بررسی شدند. در فایل‌های tracked با الگوهای رایج کلید خصوصی، AWS، GitHub و OpenAI تطبیقی پیدا نشد؛ این بررسی جایگزین اسکن کامل تاریخچهٔ Git نیست.

## وابستگی‌ها

Next.js از 16.3.3 به 16.3.8، Drizzle ORM به 0.45.4، Nodemailer به 10.1.1 و Tiptap به 3.32.0 ارتقا یافتند. SheetJS 0.20.3 از [منبع رسمی](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/) با integrity در lockfile نصب می‌شود. وابستگی‌های استفاده‌نشدهٔ Cloudinary و Prisma Accelerate حذف و نسخه‌های آسیب‌پذیر بعضی وابستگی‌های غیرمستقیم اصلاح شدند.

اسکن اولیه: ۶۰ هشدار شامل ۲ بحرانی، ۲۴ بالا و ۳۴ متوسط. اسکن نهایی `npm audit --omit=dev`: صفر هشدار. اسکن کامل: ۵ هشدار بالا با یک منشأ در زنجیرهٔ ESLint، یعنی `braces`؛ [اعلان رسمی](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) هنوز نسخهٔ اصلاح‌شده‌ای معرفی نکرده است. این مسیر ابزار توسعه است و ورودی HTTP سایت به آن داده نمی‌شود. Downgrade ناامنِ Next/ESLint پیشنهادی توسط audit اعمال نشد.

## نتیجهٔ اعتبارسنجی

- Build تولید و TypeScript موفق.
- مجموعهٔ کامل: ۳۸۸ تست، ۳۷۵ موفق، صفر ناموفق، ۱۳ تست اختیاری skip. مجموعهٔ امنیتی با دیتابیس آزمایشی: ۱۷ تست موفق، صفر ناموفق.
- تست‌های امنیتی روی PostgreSQL 17 در دیتابیس موقت و جداگانه اجرا شدند: مصرف یک‌بارهٔ reset/OTP، سقف پنج تلاش موازی، تغییر رمز هم‌زمان، ابطال رمز ثبت‌نام تأییدنشده هنگام اتصال گوگل، اجرای migration جدید، و ماندگاری rate limit در پردازش جدید.
- کنترل مبدأ production، Host جعلی، حجم واقعی stream برای JSON و multipart، JWT، لینک پروفایل و واردسازی معمول XLSX تست شدند. مسیرهای multipart کنترل مبدأ را در parser مشترک اجرا می‌کنند و از proxy مستثنا هستند تا سقف clone پیش‌فرض ۱۰ MiB در Next.js، batch مجاز را قطع نکند.
- ESLint بدون خطا؛ ۶ هشدار موجود در فایل‌های UI باقی است.
- اجرای سرور محلی production برای تست HTTP توسط بررسی خودکار مجوز رد شد؛ علت جزئی اعلام نشد. بنابراین تست HTTP نسخهٔ در حال اجرا، SMTP واقعی و Google OAuth واقعی انجام نشده‌اند.
- PostgreSQL آزمایشی متوقف شد. حذف بازگشتی پوشهٔ موقت توسط بررسی خودکار مجوز رد شد و علت جزئی اعلام نشد؛ پوشهٔ `C:\Users\AMIRHO~1\AppData\Local\Temp\ghafaseh-security-20261014` با داده‌های مصنوعی باقی است.
- حذف فایل‌های گزارش موقت `security-*.tmp` در workspace نیز توسط بررسی خودکار مجوز رد شد. این فایل‌ها از Git و Docker context کنار گذاشته شده‌اند و جزو تغییرات قابل‌انتشار نیستند.

تکرار سریع: `npm run test:security` و `npm run security:audit`. برای تست دیتابیس، `SECURITY_TEST_DATABASE_URL` باید فقط به دیتابیس محلیِ قابل‌حذف با نام `ghafaseh_security_test` و schema آماده اشاره کند. تست migration در همین دیتابیس، جدول rate limit را دوباره ایجاد می‌کند.

## نکات لازم برای استقرار

1. migration `0076_security_rate_limits` باید پیش از شروع نسخهٔ جدید اجرا شود؛ مسیر استقرار Docker فعلی migration را اجرا می‌کند. از `db:push` روی production استفاده نکنید.
2. `JWT_SECRET` باید مقدار تصادفی واقعی با حداقل ۳۲ کاراکتر داشته باشد. دامنهٔ HTTPS دقیق سایت را در `NEXT_PUBLIC_APP_URL`/`APP_URL` تنظیم کنید.
3. `TRUSTED_CLIENT_IP_HEADER` را فقط پس از تأیید رفتار reverse proxy تنظیم کنید؛ مثلاً `x-forwarded-for` وقتی ingress آدرس واقعی اتصال را اضافه می‌کند و دسترسی مستقیم به origin بسته است. بدون آن، محدودیت IP برای همهٔ کاربران مشترک خواهد بود.
4. برای مدیر فعلی، نقش دیتابیس `ADMIN` یا مالکیت تأییدشدهٔ ایمیل را بررسی کنید. حسابی که قبلاً صرفاً به‌دلیل ایمیل تأییدنشده مدیر محسوب می‌شد، دیگر مدیر نیست.
5. پیشوند جدید کوکی، کاربران production را یک‌بار از نشست قدیمی خارج می‌کند. OTPهای صادرشده با هش قدیمی نیز باید دوباره درخواست شوند. اتصال گوگل به حساب تأییدنشده نیاز به تعیین رمز جدید با بازیابی ایمیل خواهد داشت.
6. محدودیت حجم و timeout خواندن درخواست و کنترل DDoS را در ingress هم اعمال کنید. برنامه اندازهٔ واقعی multipart را تا ۱۲ MiB برای آپلود تکی و ۱۲۸ MiB برای batch مدیر محدود می‌کند؛ این کنترل جایگزین محدودیت اتصال و پهنای باند در ingress نیست.

CSP فعلی هنوز برای سازگاری با HTML ایستا و اسکریپت‌های Next.js، `unsafe-inline` دارد؛ سیاست سخت‌گیرانهٔ مبتنی بر nonce و تغییر رفتار cache در این کار پیاده‌سازی نشده است. فایل‌های تصویری با URL عمومی سرو می‌شوند؛ خصوصی‌بودن پروفایل به‌معنی private ACL برای فایل‌های storage نیست. زیرساخت واقعی، firewall، TLS، مجوزهای S3، backup واقعی و تاریخچهٔ کامل اسرار ارزیابی نشده‌اند.
