# بهینه‌سازی صفحهٔ کتاب — ۲۰۲۶/۱۰/۰۲

علت‌های قابل مشاهده در کد: خواندن دوبارهٔ کتاب و نسخه‌ها برای متادیتا، اجرای پشت‌سرهم کوئری‌های مستقل، انتظار صفحه برای پیشنهادها و محتوای کاربران، و نبود ایندکس برای ارتباط‌های پرتکرار کتابخانه و یادداشت‌ها.

تغییرات:

- دادهٔ کتاب و نسخه‌ها با `React.cache` در همان درخواست مشترک می‌شوند؛ اطلاعات کاربران بین درخواست‌ها کش نمی‌شود.
- اطلاعات اصلی از محتوای کاربران جدا شده است. مجله، یادداشت‌ها/نقل‌قول‌ها و کتاب‌های مشابه در مرزهای مستقل `Suspense` از سرور ارسال می‌شوند.
- کوئری‌های مستقل هم‌زمان اجرا می‌شوند. ردیف کتابخانهٔ نسخهٔ انتخابی با یک کوئری پیدا می‌شود.
- سه حس‌وحال پرتکرار در PostgreSQL محاسبه می‌شوند؛ همهٔ ردیف‌های کتابخانه به Node منتقل نمی‌شوند.
- نقل‌قول‌ها مستقیماً با زیرکوئری کتاب کانونی فیلتر می‌شوند. شمارش پسندها از ایندکس یکتای ارتباط‌ها استفاده می‌کند و فهرست کامل برای پسندها گروه‌بندی نمی‌شود.
- صفحه‌های یادداشت‌ها، مطالعهٔ من، API یادداشت‌ها و لینک کوتاه، داده‌های اضافی صفحهٔ کامل را نمی‌خوانند.
- migration شمارهٔ `0065` ایندکس‌های کتابخانه، نسخه‌ها، یادداشت‌ها و نام مرجع را ایجاد می‌کند. روی دیتابیس محلی `localhost/qafaseh` اعمال و وجود ایندکس‌ها تأیید شد.
- pool اتصال دیتابیس در توسعه، بین reloadها مشترک است.
- پاسخ صفحه‌های کتاب، هدر `X-Accel-Buffering: no` دارد تا Nginx ارسال تدریجی را buffer نکند.

مقایسهٔ HTTP روی صفحهٔ «ژرمینال»، با build واقعی production و دیتابیس محلی؛ میانهٔ پنج درخواست پس از یک درخواست اولیه:

| معیار | پیش از تغییر | پس از تغییر |
| --- | ---: | ---: |
| دریافت هدر پاسخ | ۵۹ ms | ۴۱ ms |
| دریافت محتوای اصلی (`h1`) | ۶۰ ms | ۴۳ ms |
| دریافت کامل HTML و دادهٔ صفحه | ۶۳ ms | ۴۵ ms |

خواندن داده‌های صفحه و متادیتا به همراه محتوای مرتبط، برای همین کتاب و کاربر مهمان، از ۲۱ کوئری به ۱۸ کوئری کاهش یافته است. ۹ کوئری مربوط به اطلاعات اصلی‌اند؛ ۹ کوئری محتوای پایین صفحه نمایش اطلاعات اصلی را متوقف نمی‌کنند. کوئری هدر سایت جدا از این اعداد است.

اندازه‌گیری محلی وضعیت شبکه، تعداد داده‌ها، بار هم‌زمان و تنظیمات reverse proxy سرور اصلی را بازتولید نمی‌کند. Chrome روی اندازه‌های ۱۴۴۰ و ۳۹۰ پیکسل بدون خطای JavaScript و overflow افقی بررسی شد. جلد اصلی بارگذاری شد؛ دریافت سرد تصویر از storage در این بررسی حدود ۲ ثانیه بود و جدا از زمان پاسخ HTML است.

در یک بررسی جداگانه با تأخیر مصنوعی ۴۰۰ ms روی کوئری‌های یادداشت و نقل‌قول، محتوای اصلی در میانهٔ ۳۴ ms دریافت شد و پاسخ کامل ۴۶۳ ms طول کشید؛ در نتیجه بخش‌های پایین صفحه واقعاً مانع ارسال محتوای اصلی نمی‌شوند. این اعداد شبیه‌سازی‌اند و اندازه‌گیری سرور اصلی نیستند.

build و lint موفق بودند. مجموعهٔ پروژه ۳۵۹ تست موفق و ۵ تست غیرفعال داشت؛ تست جدید دیتابیس نیز جداگانه با `.env` اجرا و موفق شد. مسیرهای کتاب، یادداشت‌ها، نقل‌قول‌ها و API یادداشت‌ها، redirect شناسهٔ قدیمی و پاسخ ۴۰۴ کتاب ناموجود بررسی شدند.

برای تکرار بررسی:

```powershell
npm run build
node node_modules/next/dist/bin/next start --port 3001
node scripts/profile-book-page.mjs http://localhost:3001/book/ژرمینال
npx tsx --env-file=.env scripts/profile-book-detail.ts ژرمینال
npx tsx --env-file=.env scripts/profile-book-detail.ts --indexes
node node_modules/tsx/dist/cli.mjs --env-file=.env --test lib/book/detail-service.test.ts
```

اسکریپت سرویس خارج از رندر React اجرا می‌شود؛ حذف کوئری‌های تکراری توسط `React.cache` فقط در درخواست واقعی Next.js فعال است.

برای استقرار، build جدید و migration `0065_book_detail_indexes` باید روی سرور اعمال شوند. مسیر Docker فعلی migration را هنگام راه‌اندازی اجرا می‌کند؛ استقرار مستقیم standalone باید migration را نیز اجرا کند. در صورت استفاده از Nginx، تنظیمات proxy نباید هدر `X-Accel-Buffering` را نادیده بگیرند. سرور اصلی در این درخواست تغییر داده نشده است.

## سرعت تغییر نسخه — ۲۰۲۶/۱۰/۰۶

تغییر نسخه در سایت اصلی کار می‌کرد، اما کند بود. روی «کتابخانه نیمه‌شب»، میانهٔ پنج درخواست گرم HTTP برای رسیدن اطلاعات اصلی ۱۳۸ ms و برای تکمیل پاسخ ۵۷۵۹ ms بود. در یک درخواست RSC جداگانه، اطلاعات اصلی در ۵۴۴ ms و کتاب‌های مشابه در ۱۲۰۷۸ ms رسیدند؛ بار و شبکهٔ سرور اصلی با محیط محلی متفاوت‌اند.

مرزهای `Suspense` پایین صفحه هنگام تغییر query همان هویت قبلی را داشتند. React در navigation داخل transition، محتوای قبلاً نمایش‌داده‌شده را نگه می‌داشت و نمایش نسخهٔ جدید نیز منتظر بخش کند کتاب‌های مشابه می‌ماند. مطابق [راهنمای React دربارهٔ reset کردن Suspense در navigation](https://react.dev/reference/react/Suspense#resetting-suspense-boundaries-on-navigation)، اکنون کلید این مرزها شامل شناسهٔ کتاب و نسخه است. اطلاعات اصلی نسخه می‌تواند پیش از تکمیل بخش‌های پایین نمایش داده شود.

انتخاب‌گر هنگام navigation نشانگر «در حال تغییر نسخه...» دارد و انتخاب دوبارهٔ نسخهٔ فعلی درخواست جدیدی ایجاد نمی‌کند. queryهای دیگر حفظ می‌شوند و موقعیت اسکرول با `scroll: false` باقی می‌ماند.

آزمون مرورگر با build واقعی production و چهار ثانیه تأخیر مصنوعی در کوئری کتاب‌های مشابه:

| معیار | پیش از اصلاح | پس از اصلاح |
| --- | ---: | ---: |
| از انتخاب «نشر مات» تا نمایش ناشر و مترجم جدید | ۴۴۳۷ ms | ۴۱۱ ms |

پس از اصلاح، در زمان نمایش نسخهٔ جدید، بخش کتاب‌های مشابه هنوز در حال بارگذاری بود و انتخاب‌گر دوباره فعال بود. تأخیر کوئری کتاب‌های مشابه حذف نشده؛ دیگر نمایش نسخه را متوقف نمی‌کند. این زمان‌ها محلی و شبیه‌سازی‌شده‌اند و تضمین زمان پاسخ سرور اصلی نیستند.

برای بازتولید دستی:

```powershell
npm run build
node --require ./scripts/profile-book-edition-delay.cjs node_modules/next/dist/bin/next start -p 3101
```

صفحهٔ `http://localhost:3101/book/کتابخانه-نیمه-شب` را باز کنید و تا نمایش کتاب‌های مشابه صبر کنید. نسخهٔ نشر مات را انتخاب کنید. ناشر، مترجم و تعداد صفحات باید پیش از تکمیل چهار ثانیه تغییر کنند؛ پایین صفحه در این فاصله وضعیت بارگذاری دارد. اسکریپت فقط با `--require` فعال می‌شود و در اجرای عادی برنامه وارد نمی‌شود.

build و lint فایل‌های تغییرکرده موفق بودند. مجموعهٔ پروژه ۳۶۵ تست موفق و ۱۲ تست غیرفعال داشت؛ تست یکپارچهٔ اطلاعات نسخه، حریم خصوصی و کتابخانه نیز جداگانه با دیتابیس محلی اجرا و موفق شد. این تغییر migration ندارد و برای اعمال روی سایت اصلی به استقرار build جدید نیاز دارد.
