# بررسی عملکرد بخش‌های اجتماعی — ۲۰۲۶/۱۰/۰۴

فید، فعالیت‌های اخیر صفحهٔ اصلی و پروفایل، صفحه‌های تکهٔ کتاب و یادداشت، دیدگاه‌ها و وضعیت دنبال‌کردن بررسی شدند.

## اصلاح‌ها

- شمارش دیدگاه‌های تکه و یادداشت فقط وقتی شناسهٔ محتوا وجود دارد اجرا می‌شود. در آزمونِ یادداشت پرطرفدار، PostgreSQL اسکن کامل جدول را انتخاب می‌کرد و همان اسکن برای فعالیت‌های مطالعه با شناسهٔ یادداشتِ خالی هم تکرار می‌شد. `EXPLAIN ANALYZE` برای فید ۲۰تایی، ۲۱ بار اسکن جدول دیدگاه‌ها نشان داد؛ پس از اصلاح فقط یک بار اجرا شد.
- لیست سه فعالیت صفحهٔ اصلی متن کامل تکه و یادداشت را از دیتابیس دریافت نمی‌کند. شناسهٔ مقصد، شمارش‌ها، وضعیت پسند و حریم خصوصی حفظ می‌شوند. فید و صفحه‌های محتوا همچنان متن کامل دارند.

## آزمون با دادهٔ حجیم

۵۰ هزار فعالیت مطالعه، یک یادداشت ۶۴ هزار بایتی و ۱۰۰ هزار دیدگاه برای همان یادداشت، در جدول‌های موقت با ایندکس‌های واقعی ساخته شدند. جدول‌ها پس از آزمون rollback می‌شوند. زمان‌ها میانهٔ هفت اجرا پس از یک اجرای اولیه‌اند؛ روی PostgreSQL محلی اندازه‌گیری شدند.

| سرویس | پیش از اصلاح | پس از اصلاح |
| --- | ---: | ---: |
| فید ۲۰ فعالیت | ۲۱۷–۲۳۴ ms | ۱۹–۲۰ ms |
| سه فعالیت صفحهٔ اصلی | ۴۷–۶۰ ms | ۲۰–۲۳ ms |
| صفحهٔ دوم فعالیت‌های پروفایل | ۱۳۲–۱۷۸ ms | ۴–۶ ms |

فید و فعالیت‌های پروفایل هرکدام یک کوئری اجرا می‌کنند. دریافت صفحهٔ اول دیدگاه‌ها سه کوئری دارد و فقط ۲۰ دیدگاه برمی‌گرداند؛ شمارش کل با ۱۰۰ هزار دیدگاه حدود ۱۶–۲۷ ms طول کشید.

حجم JSON خروجی سرویسِ سه فعالیت صفحهٔ اصلی برای این یادداشت بلند از ۶۸٬۱۷۹ به ۱٬۷۷۷ بایت رسید. این کاهش مربوط به دادهٔ سرویس و خواندن متن از دیتابیس است؛ متن کامل در نسخهٔ قبلی هم توسط کامپوننت سروریِ این لیست به مرورگر فرستاده نمی‌شد.

## نسخهٔ تولید

پس از build، با کاربر موقتِ دنبال‌کننده و داده‌های واقعی محلی، همهٔ مسیرهای زیر پاسخ ۲۰۰ دادند. کاربر آزمون در پایان حذف شد.

| مسیر | میانهٔ دریافت کامل پاسخ |
| --- | ---: |
| صفحهٔ اصلی | ۳۸ ms |
| فید | ۱۹ ms |
| پروفایل | ۳۸ ms |
| API فید | ۹ ms |
| صفحهٔ تکهٔ کتاب | ۱۳ ms |
| صفحهٔ یادداشت | ۲۰ ms |
| API دیدگاه‌ها | ۴ ms |

اسکریپت‌های اولیهٔ این صفحه‌ها حدود ۳۱۷–۳۵۳ هزار بایت gzip دارند؛ این عدد شامل کد مشترک Next/React و کل سایت است. کد سنگین Tiptap/ProseMirror در اسکریپت‌های اولیهٔ هیچ‌کدام نبود. فرم‌های ویرایش با `next/dynamic` و فقط هنگام باز شدن دریافت می‌شوند. این اصلاح‌ها کد کلاینت را تغییر نداده‌اند و اندازهٔ اسکریپت‌های اولیه افزایش نیافته است.

build، typecheck، lint فایل‌های تغییرکرده و ۱۸ تست بخش اجتماعی، شامل API، موفق بودند؛ تست غیرفعال یا ناموفق وجود نداشت.

این اعداد سنجش محلی سرور و دیتابیس‌اند؛ زمان نمایش روی موبایل، Core Web Vitals، اینترنت واقعی و ترافیک هم‌زمان سرور اصلی را اندازه نمی‌گیرند.

## تکرار بررسی

```powershell
npm run perf:social
```

برای افزودن سنجش HTTP، یک build تولید محلی اجرا کنید و آدرس آن را بدهید:

```powershell
$env:PERF_BASE_URL = 'http://localhost:3001'
npm run perf:social
```

آزمون HTTP از کاربر عمومی `varmanli` برای انتخاب محتوای موجود استفاده می‌کند و فقط آدرس localhost می‌پذیرد. `.env` باید دیتابیس و کلید امضای مشترک با سرور محلی را داشته باشد. سنجش HTTP شامل درخواست گرم و اندازهٔ gzip محاسبه‌شده است؛ اندازهٔ واقعی انتقال شبکه ممکن است به فشرده‌سازی سرور بستگی داشته باشد. سنجش سرویس‌ها شامل تبدیل نتیجه به JSON است.
